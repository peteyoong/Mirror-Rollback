## 1. Executive Summary

PFS-2.1 introduces a **topology-first** branch in
`services/mirror_chat_phase4_enrichment.resolve_target_via_forums`. For every
forum-membership name match, the resolver now performs a directed lookup in
`forum_relationship_edges` (forum_id × from_user_id → to_user_id) and, if an
edge exists, **prefers the edge's `role_type` over the forum-name regex**.

## 2. Resolution Precedence Ladder (PFS-2.1)

Implemented order — first match wins:

1. **`forum_relationship_edges`** — explicit directed edge for
   `(forum_id, from_user_id, to_user_id)`. Edge `role_type` maps to a
   `(resolution_source, role)` pair via `_ROLE_TYPE_TO_SOURCE`
   (e.g. `spouse → (pair_forum, spouse)`,
   `child → (family_forum, child)`,
   `cofounder → (business_forum, cofounder)`,
   `mentor → (business_forum, mentor)`).
2. **`forum_members` role mapping** (PFS-1 forum-name regex baseline).
3. **`saved_people` mapping** (resolved upstream by V2; the resolver
   short-circuits when `relationship_resolution.target` is already bound).
4. **PFS-1 heuristic fallback** (`_classify_forum_source`).

Matches with `via_topology=True` are sorted to the head of the candidate
list before the existing source-priority sort, so a topology edge in a
family forum will beat a forum-name pair match if both exist.

## 5. Information Preservation Audit

> Goal: prove that PFS-2.1 **preserves** signals that the PFS-1 regex
> discarded, not merely that it can find the spouse.

### Before vs After — `Pete & Mel`

| Path                                  | source     | role     | Notes |
|---------------------------------------|------------|----------|-------|
| **BEFORE** PFS-1 regex                | `pair_forum` | `None` | Forum name `Pete & Mel` matched the pair regex but PFS-1 Defect-2 fix deliberately refuses to assert a romantic role from a bare pair name → **spouse role was lost.** |
| **AFTER** PFS-2.1 topology-first      | `pair_forum` | **`spouse`** | Explicit edge `spouse / high / explicit` consumed; role surfaced exactly as edge stored. |

**Outcome:** `spouse → None` becomes `spouse → spouse`. ✓

### Before vs After — `Yoong family`

| Path                                  | source        | role      | Notes |
|---------------------------------------|---------------|-----------|-------|
| **BEFORE** PFS-1 regex                | `family_forum` | `family` | Regex matched family forum → only `family` role was surfaced. **Spouse signal was discarded.** |
| **AFTER** PFS-2.1 topology-first      | `pair_forum`  | **`spouse`** | Top match (highest precedence) uses the topology edge; **AND** `all_forums_with_match[]` carries the Yoong family row with `heuristic_source='family_forum'`, `heuristic_role='family'` — so the family signal is **preserved** in the receipt, not erased. |

**Outcome:** `spouse → family` (only) becomes `spouse (top) + family (preserved in secondary match)`. ✓

This is the critical PFS-2.1 invariant the user demanded: the
topology-first implementation **does not destroy information** that the
heuristic had — it adds the explicit edge on top and keeps the
heuristic baseline alongside.
